## 13 апреля — Синхронизация схемы ролей (сессия 14)

**Баг:** смена роли через `/admin/users/edit` не применялась. Форма писала только в старое строковое поле `user.role`, а проверка прав смотрела сначала в новую таблицу `user_role` (many-to-many), которая оставалась со старыми данными.

**Решение:** функция `_sync_user_roles_table()` в `app/users.py` — при каждом сохранении формы синхронизирует обе схемы. Теперь смена роли в админке сразу применяется.

## 13 апреля — Роли классных руководителей (сессия 20)

**Критический баг обнаружен при аудите:** все 116 классных руководителей в базе имели роль `TEACHER` вместо `CLASS_TEACHER`. Из-за этого у них не работали:
- Раздел «Мой класс»,
- Социальные паспорта,
- Ограничение видимости классом,
- Реестры и пропуска.

**Решение:** одной SQL-миграцией всем 116 пользователям, привязанным к классам (113 `TEACHER` + 2 `VIEWER` + 1 `ADMIN`), проставлена роль `CLASS_TEACHER` одновременно в `user.role` и `user_role`. Код не менялся — только данные.

## 13 апреля — P0+P2 аудит: безопасность уровня приложения (сессия 25)

Главный блок по безопасности:

- **CSRF-защита** — подключён `Flask-WTF` CSRFProtect. Во всех формах мета-тег с токеном, для fetch-запросов JS автоматически подкладывает токен в заголовок. Защита от подделки межсайтовых запросов.
- **Переписан декоратор `require_roles`** — теперь использует `has_any_role()` из `permissions.py`. Убраны расхождения между старой и новой схемой ролей.
- **Гамбургер-меню для мобильных** — navbar-toggler + collapse + CSS, теперь система нормально открывается с телефона.
- **Cookie безопасности** — `HttpOnly`, `SameSite=Lax`. Защита от кражи сессии через XSS и межсайтовых атак.

**Важно для установки:** после этой правки в `requirements.txt` появилась зависимость `Flask-WTF` — она уже включена в эту копию.

## Как применить свежую копию

1. Скачать архив / клонировать репозиторий с GitHub.
2. Следовать инструкции в [SETUP.md](SETUP.md) — там подробная установка под Mac и Windows.
3. Базу заново инициализировать: `flask --app run init-db` → `flask --app run repair-runtime-columns` → `flask --app run seed-academic-year` → `flask --app run seed-olympiads`.
4. Создать админа: `python init_admin.py` → `admin` / `admin123`.
5. Запустить: `python run.py` → http://localhost:5001

Старая база данных `app.db` из предыдущей версии копии **несовместима** (добавлены новые таблицы и поля). Её нужно удалить перед инициализацией — или запускать рядом с пустой.
