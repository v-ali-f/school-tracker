# Этап 7. Согласование, утверждение и документы

## Результат этапа

Реализован управляемый жизненный цикл тарификации:

```text
черновик
-> автоматическая проверка
-> содержательная проверка
-> кадровая проверка
-> финансовая проверка
-> утверждение директором
-> действующая версия
```

Переходы выполняются последовательно. Версия с блокирующими ошибками,
устаревшим расчётом или незакрытыми замечаниями не может быть направлена
на согласование или утверждена.

Действующий Excel-импорт кафедральной тарификации не изменён. Переключение
кафедр на новый источник относится к этапу 8 и будет выполняться только
после параллельной сверки.

Для документов используется стабильный `scope_key`, поэтому редакции
общего, кафедрального и персонального документа не пересекаются.

## Автоматическая проверка

Перед согласованием и повторно перед утверждением контролируются:

- дата действия версии и её принадлежность учебному году;
- наличие и готовность планов;
- наличие строк учебного плана;
- готовность групп и их численность;
- наличие потребностей и полнота распределения;
- активность назначенных сотрудников;
- наличие успешного расчёта;
- совпадение текущих входных данных с хешем расчётного снимка;
- отсутствие незакрытых блокирующих замечаний;
- обязательное основание корректирующей версии;
- ручная проверка периода и годовых часов скопированных назначений.

Результат каждой проверки хранится отдельно и не перезаписывает предыдущий.

## Согласование

Обязательный порядок:

1. `ACADEMIC` — содержательная проверка.
2. `HR` — кадровая проверка.
3. `FINANCE` — финансовая проверка.
4. `APPROVAL` — решение директора.

Проверяющий может добавить блокирующее замечание или рекомендацию. Ответ
вносит владелец данных, а закрывает замечание только его автор. Решение
`CHANGES_REQUESTED` возвращает версию в черновик и завершает текущий раунд.
После исправлений создаётся новый раунд с новой полной проверкой.

## Утверждение

Перед положительным решением система:

- повторно выполняет полный контроль;
- проверяет актуальность расчёта;
- вычисляет контрольную сумму версии, расчёта и заключений;
- сохраняет решение и дату начала действия;
- блокирует планы и расчётные параметры;
- подтверждает назначения педагогов;
- сохраняет переходы статусов в журнале.

Если дата начала действия наступила, версия сразу получает статус
`EFFECTIVE`. Предыдущая действующая версия получает статус `SUPERSEDED`,
а её период заканчивается накануне начала новой версии.

## Изменения в течение года

Корректировка создаётся только из утверждённой или действующей версии.
Система переносит в новый черновик:

- снимки контингента;
- планы, строки, области и периоды;
- группы и состав;
- потребности в часах;
- назначения педагогов;
- нормы, коэффициенты и доплаты.

Расчёт, заключения и документы не копируются. Скопированные назначения
сохраняют ссылку на исходную строку. Пользователь обязан открыть каждую
строку, проверить укороченный период и пересчитать годовые часы. Без этого
корректирующая версия не пройдёт проверку.

## Документы

Поддержаны Word-формы:

- сводный тарификационный список;
- персональный тарификационный лист;
- протокол проверки и согласования;
- лист утверждения;
- проект приказа об установлении нагрузки;
- проект приказа об изменении нагрузки.

Документы черновой версии получают отметку `ПРОЕКТ`. Официальный статус
возможен только для утверждённой версии с контрольной суммой. Для каждого
файла сохраняются редакция, расчётный запуск, SHA-256, размер, версия
шаблона и автор формирования.

Номер и дата приказа не присваиваются в модуле тарификации. Это выполняет
действующий модуль приказов после регистрации документа.

## Интерфейс

Добавлены страницы:

- `/workload/workflow/` — проверка, замечания, заключения, утверждение и
  создание версии изменения;
- `/workload/documents/` — формирование, история редакций и скачивание
  документов.

Основные таблицы остаются компактными. Подробности ошибок, ответов и
решений показываются внутри соответствующего рабочего раздела.

## Доступ

- содержательная проверка: `workload.review.academic`;
- кадровая проверка: `workload.review.hr`;
- финансовая проверка: `workload.review.finance`;
- утверждение и создание корректирующей версии: `workload.approve`;
- формирование документов: `workload.documents.generate`;
- финансовые формы дополнительно требуют `workload.finance.read`;
- педагог может скачать только собственный персональный документ;
- аудиторы могут читать доступные им сформированные материалы.

Все изменения дополнительно требуют включённого флага записи модуля.

## Границы этапа

На этом этапе ещё не выполняются:

- замена Excel-источника в производственном разделе кафедр;
- автоматическая передача приказа в реестр приказов;
- электронная подпись;
- массовая рассылка педагогам;
- выгрузка в конкретную бухгалтерскую систему;
- автоматическая активация будущей версии фоновым заданием.

Будущую утверждённую версию пока вводит в действие директор вручную после
наступления даты. Автоматическое фоновое переключение будет добавлено
вместе с эксплуатационным контуром.

## Следующий этап

Этап 8 должен выполнить безопасную интеграцию:

1. построить представления действующей нагрузки для кафедр;

3. исправить найденные расхождения;
4. переключить только чтение кафедр на утверждённый внутренний источник;
5. оставить исторический Excel-импорт для архивных данных;
6. сохранить feature flag и быстрый откат на старый источник.
