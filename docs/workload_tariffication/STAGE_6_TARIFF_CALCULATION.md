# Этап 6. Расчёт тарификации

## Результат этапа

Реализован предварительный расчёт тарификации по утверждённой на этапах
3–5 цепочке данных:

```text
учебный план -> группа -> потребность -> назначение педагога
-> набор расчётных параметров -> расчётная строка -> компоненты суммы
```

Расчёт выполняется только для черновой версии тарификации. Каждый запуск
создаёт неизменяемый снимок исходных значений, формулы, коэффициентов,
доплат и результатов. При неизменных входных данных повторный запуск
возвращает ранее выполненный успешный расчёт и не создаёт дубликат.

Действующая Excel-тарификация кафедр не изменена и остаётся производственным
источником до отдельного этапа интеграции.

Миграция `d31a7f4e9b20` добавляет таблицы:

| `tariff_allowance_rule` | Суммы, проценты и условия доплат |
| `tariff_calculation_run` | Запуск расчёта и диагностический протокол |
| `tariff_line` | Неизменяемый результат по назначению педагога |
| `tariff_line_component` | Входы, коэффициенты, доплаты и итог строки |

В `workload_assignment` добавлен стабильный код должности `position_code`.
Текущая кадровая модель проекта не содержит отдельного справочника
должностей, поэтому используется переходный код `TEACHER` и сохранённое
название `position_title`. Это решение не препятствует последующей связи с
полноценным кадровым справочником.

Снимки формул, условия правил и протоколы хранятся в PostgreSQL `JSONB`.

## Параметры

Числовые нормативы не зашиты в программный код. Пользователь с финансовыми
полномочиями задаёт для конкретной версии:

- стоимость ученико-часа;
- число расчётных периодов в году;
- правило денежного округления;
- норму часов на ставку по должности и виду деятельности;
- коэффициент деления по нормативной наполняемости;
- коэффициент сложности;
- фиксированные и процентные доплаты;
- периоды действия и текст основания каждого правила.

Система создаёт только семантические типы правил. Значения `37`, `25`,
`1,4`, `18` и суммы доплат вводятся в настройках организации и могут
изменяться между версиями.

## Формулы

Для каждой строки назначения рассчитываются:

```text
доля ставки = недельные часы / недельная норма должности

основная оплата =
  стоимость ученико-часа
  × расчётная численность группы
  × часы за период
  / количество расчётных периодов

итог =
  основная оплата
  + компоненты коэффициентов
  + компоненты доплат
```

Поддержаны виды коэффициентов:

- множитель;
- процент от основной суммы;
- отношение нормативной наполняемости к фактической.

Поддержаны фиксированные и процентные доплаты. Доплата уровня сотрудника
включается один раз, а не в каждую строку его нагрузки. Для каждого
компонента сохраняются исходное значение, сумма до округления, итоговая
сумма, выражение и ссылка на правило.

## Сверка с расчётным образцом

Автоматический тест воспроизводит строку из предоставленного примера:

| Показатель | Значение |
|---|---:|
| Часов в неделю | 5 |
| Учебных недель | 34 |
| Часов за период | 170 |
| Норма на ставку | 18 |
| Доля ставки | 0,277778 |
| Численность группы | 15 |
| Стоимость ученико-часа | 37 |
| Основная оплата | 7 862,50 |
| Доплата за деление при нормативе 25 | 5 241,67 |
| Доплата за сложность 1,4 | 3 145,00 |
| Фиксированная доплата | 16 000,00 |
| Итог | 32 249,17 |

Правила округления применяются контролируемо, а значения до округления
остаются в расчётном снимке.

## Интерфейс

Добавлены:

- `/workload/tariffication/` — версии, запуски и расчётные строки;
- `/workload/tariffication/settings/` — наборы параметров;
- форма создания набора параметров;
- карточка параметров с нормами, коэффициентами и доплатами;
- протокол запуска расчёта;
- подробная расшифровка строки и всех компонентов;
- отображение доли ставки в карточке преподавателя;
- отображение денежной суммы только пользователям с финансовым доступом.

Черновой неуспешный запуск сохраняет диагностические строки и перечень
ошибок. Действующим результатом может считаться только запуск со статусом
`SUCCEEDED`.

## Доступ

- просмотр реестра требует `workload.read`;
- денежные значения и настройки требуют `workload.finance.read`;
- изменение настроек и запуск расчёта требуют `workload.calculate` и
  включённый флаг записи;
- ограничения по кафедрам и зданиям применяются сервером;
- преподаватель видит свою нагрузку и долю ставки, но не финансовые суммы,
  если у него нет отдельного финансового разрешения.

Просмотр страницы настроек не изменяет базу данных. Коэффициент или доплата
не могут быть подключены из другой организации.

## Границы этапа

На этом этапе ещё не реализованы:

- утверждение и блокировка тарификации;
- согласование учебной, кадровой и финансовой службами;
- приказы, уведомления и дополнительные соглашения;
- переключение кафедр с Excel на новый источник;
- автоматическая весовая численность по отдельным категориям обучающихся.

До появления модели категорий расчёт использует фактическую численность
группы, а при её отсутствии — плановую. Весовые категории должны быть
добавлены и сверены с локальными нормативами до производственного перехода.
