# Этап 8. Интеграция с кафедрами и переключение источника

## Результат

Этап завершает локальную цепочку:

`учебный план -> группы -> нагрузка -> расчёт -> согласование -> утверждение
-> кафедры`.

Кафедры больше не обязаны постоянно получать действующую нагрузку из
Excel. При этом старый источник не удалён: он остаётся архивным источником,
контрольным снимком для сверки и средством быстрого отката.

Школьный сервер в ходе этапа не использовался и не изменялся.

## Режимы источника

Для каждого учебного года хранится один из режимов:

| Режим | Чтение кафедр | Изменение Excel |
|---|---|---|
| `LEGACY` | `teacher_load` | Разрешено администратору |
| `COMPARE` | `teacher_load` | Заблокировано на время сверки |
| `INTERNAL` | утверждённая внутренняя нагрузка | Заблокировано |

Глобальный флаг `FEATURE_WORKLOAD_NEW_SOURCE_ENABLED` является аварийным
выключателем. Если он выключен, фактическим источником всегда становится
`LEGACY`, даже когда в базе настроен `INTERNAL`.

## Условия переключения

Режим `INTERNAL` можно включить только если одновременно выполнены условия:

1. версия имеет статус `EFFECTIVE`;
2. версия относится к выбранному учебному году;
3. существует успешный расчёт тарификации;
4. выполнена последняя сверка с Excel;
5. сверка имеет статус `PASSED`;
6. блокирующие расхождения отсутствуют;
7. внутренний источник содержит хотя бы одну строку.

Пустой внутренний источник нельзя сделать действующим.

## Внутренняя витрина

Кафедральная нагрузка строится из последнего успешного расчёта действующей
версии. В витрину попадают только:

- подтверждённые назначения;
- назначения конкретных сотрудников;
- строки, не являющиеся вакансиями;
- данные выбранного учебного года;
- связи с единым каталогом дисциплин, кафедрой и зданием.

Каждая строка показывает:

- педагога;
- учебный год;
- дисциплину;
- кафедру;
- группу;
- здание;
- недельные часы.

Финансовые суммы в старую кафедральную таблицу не передаются.

## Параллельная сверка

Сверка агрегирует оба источника по ключу:

`педагог + образовательная активность + кафедра + здание`.

Сравниваются недельные часы с допуском `0.001`.

Статусы строки:

- `MATCH`;
- `HOURS_MISMATCH`;
- `LEGACY_ONLY`;
- `INTERNAL_ONLY`;
- `UNMAPPED_ACTIVITY`.

Любой статус, кроме `MATCH`, блокирует переход на внутренний источник.
Результаты каждой сверки неизменяемо сохраняются вместе с идентификаторами
исходных строк.

## Интерфейс

Административный экран:

`/workload/integration/`

Он позволяет:

- выбрать учебный год;
- увидеть настроенный и фактический источник;
- проверить состояние feature flag;
- запустить сверку;
- открыть подробности расхождений;
- перейти в `COMPARE`;
- включить `INTERNAL`;
- немедленно вернуться в `LEGACY`;
- сохранить основание каждого перехода.

Страницы:

- `/departments/loads`;
- `/departments/summary`

показывают фактический источник. Формы импорта и ручного редактирования
скрываются, когда Excel зафиксирован для сверки или используется внутренний
источник.

## Что не удалено

- таблица `teacher_load`;
- действующий Excel-парсер;
- архивные строки прошлых лет;
- ручной возврат к старому источнику;
- feature flag аварийного отключения.

Регулярный импорт текущей тарификации прекращается только после успешного
производственного переключения. До этого момента режим остаётся `LEGACY`.

## Проверка

Автоматически проверены сценарии:

- точное совпадение источников;
- несовпадение часов;
- блокировка перехода при расхождениях;
- запрет пустого внутреннего источника;
- переключение `COMPARE -> INTERNAL`;
- возврат `INTERNAL -> LEGACY`;
- аварийное действие feature flag;
- чтение внутренней нагрузки страницей кафедр;
- сокрытие Excel-импорта при внутреннем источнике.

Всего проходит `81` тест.

Поэтому реальная сверка школьной тарификации ещё не выполнялась. Для неё

локальную среду, не подключая приложение к школьной базе напрямую.

## Порядок производственного перехода

1. Создать резервную копию файлов и PostgreSQL на школьном сервере.
2. Развернуть релиз с тремя feature flags, оставленными выключенными.
3. Выполнить миграции Alembic.
4. Включить модуль и запись, оставить новый источник выключенным.
5. Подготовить и ввести в действие внутреннюю версию тарификации.
6. Включить `FEATURE_WORKLOAD_NEW_SOURCE_ENABLED=1`.
7. Установить режим `COMPARE`.
8. Выполнить сверку и устранить все расхождения.
9. Зафиксировать протокол приёмки.
10. Переключить выбранный учебный год в `INTERNAL`.
11. Проверить кафедры, карточки педагогов, МЦКО, контрольные и олимпиады.
12. При ошибке выключить feature flag или выбрать `LEGACY`.

До отдельного согласованного релиза эти действия на школьном сервере не
выполняются.
