# Этап 6. Визуальная и регрессионная проверка

## Результат

Завершена проверка единого рабочего пространства учебного планирования и
нагрузки после этапов 1–5.

Проверка выполнялась только в локальной среде:

`http://127.0.0.1:5002`

Школьный сервер, production-конфигурация и production-база не
использовались.

## Проверенные экраны

- рабочее пространство и режимы;
- матрица часов;
- группы и метагруппы;
- распределение нагрузки;
- проверка и согласование;
- тарификация;
- документы;
- интеграция и источник кафедр.

## Проверенные размеры

- desktop: `1440 x 900`;
- mobile: `390 x 844`.

На обоих размерах проверялись:

- ширина документа;
- локальная прокрутка широких таблиц;
- размещение основных и контекстных панелей;
- переключатели режимов;
- сводные показатели;
- формы и кнопки;
- отсутствие ошибок в консоли браузера.

## Исправления по результатам проверки

### Общие стили контроля

Общие классы сегментированной навигации, сводных блоков и правой
контекстной панели подключены для всех страниц рабочего пространства.
Устранено сжатое отображение навигации этапа 5.

### Заголовки

Заголовки контрольных экранов переведены в спокойное неоформленное
представление без дополнительной плавающей карточки.

### Рабочее место нагрузки

Рабочее место автоматически выбирает последнюю доступную черновую версию.
Потребности разных версий больше не объединяются в одном представлении.
Добавлен явный фильтр `Учебный год и версия`.

### Мобильная матрица

При первом открытии матрицы выбранная строка готова к редактированию, но
контекстная панель не перекрывает таблицу автоматически. Панель
открывается после осознанного выбора ячейки.

### Кэш статических ресурсов

Обновлены версии CSS и JavaScript, чтобы браузер получил итоговую
редакцию без ручной очистки кэша.

## Итоги адаптивной проверки

- внешнего горизонтального переполнения документа нет;
- широкая матрица прокручивается только внутри своей области;
- широкие служебные таблицы прокручиваются внутри таблицы;
- режимы на мобильном экране представлены компактными значками;
- боковые панели работают как выдвижные;
- формы интеграции перестраиваются из двух колонок в одну;
- новый источник кафедр остаётся недоступен при выключенном feature flag;
- ошибок и предупреждений JavaScript в проверенных сценариях нет.

## Автоматические проверки

- синтаксис Jinja-шаблонов проверен;
- Python-модули компилируются;
- `git diff --check` проходит;
- целевая выборка: `57 passed`;
- полный набор: `85 passed`.

Имеющиеся предупреждения относятся к ранее существующим вызовам
`datetime.utcnow()` и legacy API SQLAlchemy. Новых ошибок они не создают.

## Состояние после этапа

Интерфейсный рефакторинг этапов 1–6 завершён локально. Бизнес-логика,
формулы, таблицы и миграции базы данных не изменялись. Переключение кафедр
на новый источник не выполнялось.

Следующий организационный шаг:

1. пользовательская проверка локального сценария;
2. фиксация изменений в Git;
3. подготовка отдельного плана тестового развёртывания;
4. резервная копия школьного сервера и базы;
5. миграции и проверка на тестовой копии;
6. отдельное согласование production-релиза и плана отката.
