# Этап 0. Техническая карта

## Назначение

Подготовить независимое локальное окружение и зафиксировать текущее состояние
проекта до разработки модуля.

## Локальный контур

- Репозиторий: отдельная локальная копия `school-tracker`.
- Ветка: `feature/workload-tariffication-local`.
- Базовый commit: `0c5cfcba2ae9ba25a75c21bfc59628993ee9fffc`.
- Python: 3.12.
- Виртуальное окружение: `.venv`.
- Локальная БД: `school_tracker_workload_local`.
- Контрольная пустая БД миграций: `school_tracker_workload_baseline_rebuild`.
- Production-секреты не копировались.
- Школьный сервер не подключался и не изменялся.

## Обследованные существующие сущности

- пользователи, роли и назначения ролей;
- учебные годы, здания, классы и контингент;
- единый реестр `subject`;
- кафедры, руководители кафедр и предметы кафедр;
- действующая Excel-нагрузка `teacher_load`;
- контрольные работы, МЦКО и олимпиады;
- настройки видимости модулей;
- текущий механизм автоматического создания схемы.

## Миграционный фундамент

- Автоматическое создание схемы можно отключить через
  `AUTO_SCHEMA_BOOTSTRAP=0`.
- Модели приведены в соответствие с таблицами и индексами, которые раньше
  создавались runtime-скриптами.
- Создана базовая миграция Alembic
  `f9487aa87d4f_baseline_current_schema`.
- Базовая миграция проверена применением к отдельной пустой локальной БД.

## Зафиксированные ограничения

- `teacher_load` остаётся действующим источником кафедральной нагрузки.
- Регулярный Excel-импорт пока не отключается.
- Схема школьной БД не меняется без резервной копии, сверки и отдельного
  плана миграции.
- Новая предметная модель должна использовать существующий `subject`, а не
  создавать параллельный справочник.
