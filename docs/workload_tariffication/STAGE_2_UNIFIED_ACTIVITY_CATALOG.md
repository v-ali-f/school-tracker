# Этап 2. Единый каталог образовательных активностей

## Результат этапа

Создан общеплатформенный каталог предметов, курсов, модулей, внеурочной
деятельности, программ дополнительного образования и олимпиадных направлений.
Каталог добавлен как совместимый слой над действующей таблицей `subject`.

Этап не переключает кафедры, контрольные работы, МЦКО, олимпиады или
расписание на новый источник данных. Старые процессы продолжают работать.

## Миграция

- Alembic revision: `2b6d8f3a91c4`.
- Предыдущая revision: `f9487aa87d4f`.
- Миграция проверена на отдельной PostgreSQL-базе полным циклом
  `upgrade -> downgrade -> upgrade`.
- После применения `flask db check` не обнаруживает расхождений между
  SQLAlchemy-моделью и PostgreSQL.

Созданы таблицы:

| Таблица | Назначение |
|---|---|
| `education_activity` | Канонический каталог |
| `education_activity_alias` | Внешние и исторические варианты названий |
| `education_activity_department` | Связи каталога с кафедрами и периоды |
| `external_activity_mapping_log` | Аудит результатов внешнего сопоставления |

В `subject` добавлен nullable FK `education_activity_id`. Поле оставлено
nullable для безопасного поэтапного внедрения, но все существующие локальные
предметы были связаны миграцией.

## Виды каталога

- `SUBJECT` - учебный предмет;
- `COURSE` - учебный курс;
- `MODULE` - учебный модуль;
- `EXTRACURRICULAR_COURSE` - внеурочный курс;
- `ADDITIONAL_PROGRAM` - программа дополнительного образования;
- `CLUB_OR_SECTION` - кружок или секция;
- `OLYMPIAD_DIRECTION` - олимпиадное направление.

Каталог хранит код, полное и краткое наименование, вид, уровень образования,
признак тарифицируемости, область организации, период действия и активность.

## Совместимость

Старые ID и внешние ключи `subject` не изменяются. При создании предмета через
действующие формы и импорты сервис автоматически создаёт связанную запись
каталога. Обновление старого предмета синхронизирует только автоматически
созданную совместимую запись с кодом `LEGACY_SUBJECT_<id>`.

На единый сервис переведены существующие пути создания предметов:

- задолженности;
- сотрудники и контингент;
- кафедры и импорт Excel-нагрузки;
- CLI начального наполнения.

Таблицы `teacher_load`, `department_subject`,
`olympiad_subject_mapping` и текущие импортные процессы не удалены.

## Сопоставление внешних названий

Сервис выполняет только детерминированное сопоставление:

1. точный код;
2. каноническое полное или краткое наименование;
3. подтверждённый алиас с учётом модуля, системы и организации.

Неизвестное или неоднозначное название не создаёт новый предмет автоматически.
Результат имеет статус `MATCHED`, `AMBIGUOUS` или `UNMATCHED` и может быть
записан в журнал для воспроизводимости импорта.

## Кафедры

Каталог поддерживает несколько кафедр с периодами действия, но только одну
текущую основную кафедру. Уникальность защищена индексами PostgreSQL и
проверяется тестами.

Данные действующей тарификации в кафедры на этом этапе не передаются. Флаг
`FEATURE_WORKLOAD_NEW_SOURCE_ENABLED` остаётся выключенным.

## Интерфейс и доступ

Добавлен реестр `/workload/catalog/` с поиском и фильтрацией. Карточка элемента
содержит алиасы, связь со старым предметом и кафедры.

- просмотр требует включённого `FEATURE_WORKLOAD_MODULE_ENABLED`;
- изменение дополнительно требует `FEATURE_WORKLOAD_WRITE_ENABLED`;
- сервер также проверяет разрешение `workload.settings.manage`;
- все флаги по умолчанию выключены.
