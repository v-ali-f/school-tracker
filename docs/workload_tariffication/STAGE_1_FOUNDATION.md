# Этап 1. Фундамент модуля

## Результат этапа

Подключён защищённый каркас модуля `Нагрузка и тарификация` без создания
учебных планов, строк нагрузки, расчётов и тарификационных версий.

## Feature flags

Все флаги имеют безопасное значение `False` по умолчанию:

| Переменная | Назначение |
|---|---|
| `FEATURE_WORKLOAD_MODULE_ENABLED` | Регистрация пользовательского доступа к каркасу |
| `FEATURE_WORKLOAD_WRITE_ENABLED` | Будущее разрешение изменяющих операций |
| `FEATURE_WORKLOAD_NEW_SOURCE_ENABLED` | Будущий переход кафедр на новый источник |

Выключенный флаг модуля скрывает карточку и возвращает `404` на
`/workload/`. Флаг записи не включается автоматически вместе с просмотром.

## Маршрут

- Blueprint: `workload`.
- URL-префикс: `/workload`.
- Начальный экран: `GET /workload/`.
- Анонимный пользователь при включённом модуле направляется на страницу входа.
- Авторизованный пользователь без права получает `403`.
- Явный запрет модуля в `RoleModuleAccess` имеет приоритет над доступом роли
  по умолчанию.

## Разрешения

Добавлены машинные коды:

- `workload.read`;
- `workload.self.read`;
- `workload.plan.update`;
- `workload.groups.update`;
- `workload.assignments.update`;
- `workload.finance.read`;
- `workload.calculate`;
- `workload.review.academic`;
- `workload.review.hr`;
- `workload.review.finance`;
- `workload.approve`;
- `workload.documents.generate`;
- `workload.audit.read`;
- `workload.settings.manage`.

Сервер проверяет разрешения независимо от видимости кнопок и карточек.

## Области данных

Создан контракт `WorkloadAccessScope`. Он предусматривает ограничения по:

- организации;
- учебному году;
- зданию;
- кафедре;
- собственным данным преподавателя.

На этапе 1:

- администратор, директор, заместитель директора, методист, кадровый
  специалист, экономист и аудитор получают полный контур в пределах
  текущей инсталляции;
- руководитель кафедры ограничивается назначенными кафедрами и зданиями;
- преподаватель ограничивается собственными данными и назначенными зданиями;
- роль без назначения получает пустую область.

Все будущие запросы модуля обязаны применять этот объект на сервере.

## Интеграция с интерфейсом

- Blueprint включён в существующий реестр модулей.
- Новый модуль добавлен в административную настройку ролей.
- Карточка на главной странице появляется только при включённом feature flag,
  наличии разрешения и видимости модуля для роли.
- Текущая карточка кафедр и экран `Нагрузка учителей` не изменены.

## Автоматические проверки

Добавлена тестовая инфраструктура `pytest` и 15 тестов, которые проверяют:

- скрытие модуля выключенным флагом;
- перенаправление анонимного пользователя;
- отказ неподходящей роли;
- доступ разрешённых ролей;
- приоритет явного запрета;
- появление карточки модуля только при включённом флаге;
- независимый флаг записи;
- области администратора, руководителя кафедры и преподавателя;
- отсутствие новых бизнес-таблиц модуля.

Команда:

```bash
XDG_CACHE_HOME=/private/tmp/altair-font-cache .venv/bin/pytest
```

## Что намеренно не сделано

- не созданы таблицы учебных планов, групп, нагрузки и тарификации;
- не изменена `teacher_load`;
- не изменён импорт Excel в кафедрах;
- не подключён новый источник данных к кафедрам;
- не выполнены изменения на школьном сервере;
- не включены feature flags в production.

## Условия перехода к этапу 2

1. Тесты этапа 1 проходят.
2. Alembic не обнаруживает незапланированных изменений схемы.
3. Локальное приложение запускается с выключенным модулем.
4. Каркас открывается только при локальном включении флага.
5. Действующие кафедры и Excel-нагрузка продолжают работать как прежде.
