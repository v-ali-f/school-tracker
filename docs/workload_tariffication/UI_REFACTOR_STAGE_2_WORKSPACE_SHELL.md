# Этап 2. Единый каркас рабочего пространства

## Результат

Все страницы модуля подключены к общему рабочему каркасу без изменения
маршрутов, SQLAlchemy-моделей, расчётных сервисов и структуры данных.

Каркас содержит:

- строку контекста учебного года и версии;
- шесть режимов: часы, группы, метагруппы, нагрузка, контроль, печать и экспорт;
- сводную строку состояния;
- левую панель структуры;
- центральную рабочую область;
- правую контекстную панель;
- служебное меню каталога, тарификации и интеграции;
- адаптивные выдвижные панели для узких экранов.

Существующие формы, таблицы, ссылки и POST-операции помещены в центральную
область без изменения их поведения. Специализированная роль преподавателя
видит только собственную нагрузку.

## Техническая реализация

- Базовый шаблон: `app/templates/workload/workspace_base.html`.
- Стили: `app/static/css/workload_workspace.css`.
- Поведение панелей: `app/static/js/workload_workspace.js`.
- Все шаблоны `app/templates/workload/*.html` наследуют общий каркас.
- Старое девятивкладочное меню скрыто внутри нового рабочего пространства,
  но его URL и обработчики сохранены.

## Миграционная целостность

Восстановлена полная цепочка Alembic:

```text
f9487aa87d4f
→ 2b6d8f3a91c4
→ 7d1f0a6b3c29
→ a4c9e12f7b63
→ c8e71b2d4f90
→ d31a7f4e9b20
→ e42b8c6f1d73
→ f53c9d7a2e84
```

Baseline восстановлен из сохранённого локального schema-only снимка этапа 0.
Цепочка применена к отдельной пустой PostgreSQL-базе. Команда
`flask db check` завершилась сообщением `No new upgrade operations detected`.

Рабочая локальная база и школьный сервер не изменялись.

## Граница следующего этапа

Этап 3 перерабатывает только режим «Часы»:

- реестр и выбор плана;

  объёма;
- контекст выбранной строки и ячейки.
